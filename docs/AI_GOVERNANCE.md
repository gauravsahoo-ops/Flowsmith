# Flowsmith Enterprise AI Governance & Safety Framework

**Version:** 1.0.0 Enterprise  
**Governance Scope:** Autonomous Agents, LLM Workflow Generation, MCP Servers, RAG Vector Stores, Auto-Repair  
**Guiding Principle:** Non-Hallucinatory Execution, Grounded Schemas, Strict Human Agency, Zero Data Egress

Flowsmith treats AI as an accelerator for orchestration, not an uncontrolled black-box executor. All AI interactions adhere to four foundational pillars:


## 2. Grounded Natural Language Workflow Generation

When a user prompts the AI Copilot:
> *"Connect Salesforce to our CRM, watch for new opportunities, enrich them with AI, retrieve company knowledge, score the lead, route it according to rules, ask a human for approval, update Salesforce, send Slack notification, and expose this workflow as an API."*

Flowsmith executes a 5-step deterministic compilation pipeline:

```
[User Prompt]
     │
     ▼
[Step 1: Catalog Grounding] ────> Extracts connector definitions from ConnectorRegistry
     │
     ▼
[Step 2: LLM DAG Drafting] ────> Emits structured JSON DAG topology
     │
     ▼
[Step 3: Pydantic AST Validation] ─> Validates against Workflow schema & parameter contracts
     │
     ▼
[Step 4: Connection & Cycle Check] -> Kahn's algorithm confirms valid DAG structure
     │
     ▼
[Step 5: Visual Canvas Injection] ─> Graph rendered in React Flow; user reviews before activate
```

### Safety Guarantees
- **Zero Raw Code Generation**: The Copilot emits graph topology and parameter bindings; it is not permitted to generate raw arbitrary shell commands or unsandboxed code scripts.
- **Contract Enforcement**: Parameters must match the exact schema expected by the connector (e.g. Salesforce object names, Slack channel formats).
- **Explicit User Activation**: Workflows generated by AI are created in an inactive state (`active: false`). They can only be triggered after human inspection and explicit activation.

## 3. Autonomous ReAct Agent Governance

Flowsmith includes an autonomous **ReAct (Reasoning + Acting) Agent Engine** (`app.ai.agent`):

### Safety Constraints & Guardrails

1. **Iteration Ceilings**:
   - Hard execution limit (default: 10 iterations) prevents runaway loops and token exhaustion.
2. **Whitelisted Tool Calling**:
   - The agent can only execute tools explicitly registered in the runtime registry.
   - Destructive operations (delete, update, promote) require elevated permissions or explicit confirmation.
3. **Structured Observation Parsing**:
   - Tool outputs are truncated and sanitized to prevent recursive context explosion.
4. **Loop Termination Criteria**:
   - Detects cyclic reasoning patterns or repeated identical tool calls and triggers a graceful fallback exit.

## 4. Human-In-The-Loop (HITL) Approvals

Critical business processes (financial transactions, customer data deletion, CRM record updates) require verified human oversight:

```
[Upstream Nodes] ──> [Approval Node] ──> Suspended (status: waiting)
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
           Slack / Email Link     Approvals Dashboard
                    │                   │
                    └─────────┬─────────┘
                              ▼
                   [HMAC-Signed Decision]
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
                Approved             Rejected
                    │                   │
                    ▼                   ▼
           [Update Salesforce]      [Alert Ops]
```

### Technical Implementation

- **Approval Node (`approval`)**:
  - Halts workflow execution and saves the state to PostgreSQL (`status: "waiting"`).
  - Generates a cryptographically signed, single-use token tied to the execution ID and expiration timestamp.
  - Dispatches an approval notification (Slack, Email, Teams) with one-click decision links.
- **Decision Ingestion (`/api/approvals/{id}`)**:
  - Validates token authenticity, user identity, and expiration.
  - Automatically resumes the paused execution branch via the AsyncIO scheduler.
  - Captures approver notes, timestamp, and user ID in the execution audit log.

## 5. Deterministic Graph Auto-Repair Architecture

When a workflow fails at runtime (e.g. an API schema drifted from `$json.user_id` to `$json.id`), Flowsmith uses a deterministic auto-repair engine:

1. **Exception Intercept**: Captures node failure type, HTTP error code, and exception message.
2. **Upstream Schema Introspection**: Traverses the DAG backward to inspect the actual keys present in the upstream node's output.
3. **AST Parameter Patch**: Computes the exact JSONPath substitution without hallucination.
4. **Interactive Review**: Displays a visual before-and-after diff to the operator (`NodeAutoRepair.jsx`), requiring approval before applying the fix.

## 6. Model Context Protocol (MCP) Governance

Flowsmith's Model Context Protocol server exposes platform capabilities to external IDEs (Cursor, Windsurf) and LLM clients (Claude Desktop):

- **Permission Scoping**:
  - Read-Only Tools (`list_connectors`, `search_knowledge`, `query_data_table`) are isolated from Mutating Tools (`trigger_workflow`).
- **Data Table Query Guardrails**:
  - SQL queries executed via `query_data_table` are restricted to tenant-owned tables.
  - DROP, TRUNCATE, ALTER, and cross-tenant joins are rejected at the parser level.
- **MCP Call Auditing**:
  - Every MCP JSON-RPC call is logged with client identification, latency, and arguments.

## 8. Agent Governance Framework & Security Guardrails

Flowsmith implements an explicit runtime governance guard (`AgentGovernanceGuard`) to prevent runaway AI executions or unauthorized resource access:

```json
{
  "max_iterations": 20,
  "max_tool_calls": 50,
  "max_cost_usd": 1.00,
  "allowed_connectors": ["salesforce", "msteams", "postgresql"],
  "allowed_domains": ["api.salesforce.com", "graph.microsoft.com"],
  "approval_required": true
}
```

### 8.1 Security Policies
1. **Zero Secret Exposure**: Flowsmith never sends raw API keys, bearer tokens, or database passwords to the LLM. Workflows use symbolic credential references (`{"salesforce": "$user"}`), and the execution engine resolves secrets at runtime inside encrypted memory.
2. **Capability-Grounded Retrieval**: The LLM is never given an uncontrolled prompt with arbitrary tool execution. Tools are discovered dynamically via `CapabilitySearch` and validated against connector specifications.
3. **Simulation-First Deployment**: Generated workflows must execute in the non-destructive simulator before deployment, verifying schema and expression validity without external mutations.
4. **Interactive Repair & Modification Diff**: When repairing or modifying workflows, Flowsmith generates structured diffs (`added_nodes`, `modified_nodes`, `connections`). Changes are never applied silently without human approval.
